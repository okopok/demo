# Агентный GitHub

Идея на одну фразу: git — это не бюрократия, а право агента на ошибку.
Пока есть ветка и дифф, любую его выходку можно откатить одной командой.

## Что должно быть готово

- `gh` авторизован на его маке: `gh auth login` (один раз, в терминале).
- Проект под git, `main` всегда рабочий.
- Ветка на каждую задачу: `fix/...`, `feat/...`.

Проверка на созвоне: `gh auth status` и `git status`.

## Цикл, который показываем

1. **Issue словами.** «На 375px тарифы разъезжаются, нужен скролл вниз, не вбок».
   Issue — это контекст, который не надо пересказывать агенту каждый раз.
2. **Ветка.** `git switch -c fix/pricing-mobile`.
3. **План и правки.** Агент читает issue, предлагает план, правит `src/`.
4. **Проверка.** `node build.mjs`, страница на 375px.
5. **Коммит.** Сообщение: что и зачем, а не «update files».
6. **PR.** `gh pr create` с описанием: что, почему, как проверить.
7. **Ревью.** Второй агент или ты читаешь дифф. Правка — тем же PR.
8. **Merge.** Issue закрывается сам (`Closes #12` в описании PR).

## Что дописать в AGENTS.md

```markdown
## Git и GitHub
- Работаем в ветке, не в main. Имя: `fix/...` или `feat/...`.
- Коммит — после подтверждения. Сообщение объясняет «что и зачем».
- `git push` и `gh pr create` — только по просьбе.
- Историю не переписываем: без `push --force` и `rebase -i`.
- Секреты не коммитим: `.env` в `.gitignore`, ключи — через `gh secret set`.
```

## CI и превью — делаем вживую

Не готовим заранее. На созвоне просим агента добавить workflow:
сборка на каждый PR, деплой `dist/` на GitHub Pages после merge.
Дальше видно главное: агент открыл PR → чек зелёный → merge → сайт обновился.

Если что-то пошло не так, это тоже материал: откат PR в один клик.

## Почему это экономит лимиты

- Не надо держать в контексте «что мы уже сделали» — это в issue и PR.
- Ревью идёт по диффу, а не по всему проекту.
- Параллельные агенты в отдельных worktree (Orca, OpenChamber) не мешают
  друг другу и не перезаписывают файлы.

## Частая ошибка

Дать агенту `gh` с правом писать в `main`. Тогда «право на ошибку» исчезает.
Правило простое: агент пушит ветку, merge делает человек.
